# Dataset Description

## Overview
This dataset contains 400,000 synthetic card transactions covering six months (2025-01-01 to 2025-06-29) at a simulated payment processor, with about 20,000 customers and 3,000 merchants. Each row is one transaction with channel, amount, merchant, device and country information, plus a binary label for confirmed fraud. About 1.07% of transactions (4,265) are fraud.

Three fraud behaviors are simulated: card-testing bursts (common early, then fading), account takeovers (throughout), and a mule-merchant ring that only begins around day 130. Confirmed fraud is learned through chargebacks, which arrive 3 to 21 days after the transaction. The data is entirely generated by the script published at the source URL below, so no real person's data is involved.

## Intended Use
This dataset is designed for building and benchmarking fraud-detection classifiers under realistic deployment conditions:
- Evaluating models on a future time period, where fraud patterns differ from the training period (concept drift).
- Handling severe class imbalance (about 1 in 100 positives) with ranking metrics such as PR-AUC.
- Testing whether validation strategy and feature engineering avoid leakage through time, shared customers and shared devices.
- Training on labels that are incomplete for recent transactions because chargebacks arrive late.

It is intended for ML research, education and benchmarking. It is not intended for production fraud decisions, because it is synthetic.

## File Structure
- `data.csv` - all 400,000 transactions with the ground-truth label and chargeback delay (raw, unsplit)

## Features
| Column | Type | Description |
|--------|------|-------------|
| transaction_id | int | Unique identifier, randomly ordered (carries no time information) |
| timestamp | datetime | Transaction time in UTC, second resolution |
| customer_id | int | Cardholder identifier (0-19,999) |
| merchant_id | int | Merchant identifier (0-2,999) |
| merchant_category | categorical | One of 12 categories such as grocery, electronics, gift_cards |
| amount | float | Transaction amount in one normalized currency (right-skewed, median 21.75, max 1,405.94) |
| channel | categorical | online / pos / atm |
| device_id | integer | Device identifier, recorded only for online transactions |
| country | categorical | Country code of the transaction (8 countries) |
| is_fraud | integer | Target. 1 = confirmed fraud, 0 = legitimate |
| label_delay_days | float | Fraud rows only: days from the transaction until the chargeback confirmed it (3-21). Empty for legitimate rows |

## Data Characteristics
- **Missing values:** merchant_category is missing in about 2% of rows and country in about 1%, at random. device_id is missing in about 54% of rows (every pos and atm transaction), which is structural. label_delay_days is empty for the 98.9% of rows that are not fraud.
- **Target distribution:** highly imbalanced, 1.07% positive overall. The positive rate varies over time, and fraud signatures differ between the early and late parts of the period.
- **Amount:** right-skewed with a long tail. ATM amounts are multiples of 20.
- **High-cardinality identifiers:** customer_id, merchant_id and device_id repeat across rows, so rows are not independent. Some devices are shared across many customers.
- **Time:** timestamp spans 180 days with daily and weekly seasonality.
- **Delayed labels:** label_delay_days records when each fraud became known. Frauds that occurred shortly before any chosen cutoff date would not yet be labeled at that cutoff.
